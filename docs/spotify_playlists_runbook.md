# Spotify Playlists Runbook

This runbook is the operator reference for the Spotify playlist workflows in this repo.

It covers:

- creating a new playlist
- refreshing client playlists
- resolving track IDs and durations
- inspecting playlist contents
- redistributing Spotify tracks inside an existing playlist
- keeping the promo workflow separate from Spotify playlist rotation

## 1. Prerequisites

Use the project virtualenv and Python 3.11.

Spotify credentials are required for any playlist write operation:

```bash
export SPOTIFY_CLIENT_ID="..."
export SPOTIFY_CLIENT_SECRET="..."
export SPOTIFY_REDIRECT_URI="http://localhost:8080/callback"
```

Recommended runtime env vars for this repo:

```bash
export MPLBACKEND=Agg
export MPLCONFIGDIR=.mplconfig
export NUMBA_CACHE_DIR=.numba_cache
```

If the CLI asks for `Client id:` interactively, it means the env vars above are not set in that shell.

## 2. Important Behavior

- Spotify deprecated the recommendations endpoint. Rotation now comes from the configured `curated_queries` and `rotation_queries`, not Spotify recommendations.
- Playlist order is controlled by this repo. A refresh rewrites the playlist in the order generated by the profile logic.
- Duques Sta Fe uses daypart-aware ordering:
  - `warmup_soul`
  - `high_energy_funk`
  - `wind_down`
- Profiles can optionally define `weekday_profiles` so each weekday can swap in a different daypart layout while keeping the same playlist shell and rotation pool.
- Duques also uses weekly seeded shuffling inside those blocks, so each week can open differently while preserving the overall barbershop flow.
- Promo audio files are separate from Spotify playlist rotation. Refreshing Spotify does not modify:
  - `promo.txt`
  - `promo_voice.mp3`
  - `promo_clip.mp3`

## 3. Main Command

General form:

```bash
python3.11 -m electro_analyzer.cli playlist \
  --profile-config profiles/<profile>.json \
  --rotation-tracks <N> \
  --max-tracks <N> \
  --force
```

Useful flags:

- `--profile-config`: JSON profile to use
- `--rotation-tracks`: number of tracks to draw from the configured rotation pool
- `--rotation-seed`: manual override to force a different curated/rotation mix outside the normal cadence
- `--rotation-cadence`: `weekly` or `daily` deterministic seed generation
- `--for-date`: resolve weekday profile overrides and cadence seeds for a specific `YYYY-MM-DD`
- `--max-tracks`: hard cap before duration trimming
- `--target-duration-hours`: stop once the playlist reaches the target runtime
- `--cooldown-days`: skip updates if refreshed recently
- `--force`: ignore cooldown
- `--dry-run`: preview without writing to Spotify
- `--playlist-name`: temporary override

If you normally rotate on Mondays but need a visibly different mix mid-week, rerun with a one-off seed:

```bash
python3.11 -m electro_analyzer.cli playlist \
  --profile-config profiles/duques.json \
  --rotation-tracks 50 \
  --rotation-seed 20260722 \
  --max-tracks 200 \
  --force
```

If you want deterministic daily refreshes for automation:

```bash
python3.11 -m electro_analyzer.cli playlist \
  --profile-config profiles/duques.json \
  --rotation-tracks 50 \
  --rotation-cadence daily \
  --for-date 2026-08-24 \
  --max-tracks 200 \
  --force
```

## 4. Create a New Playlist

The `playlist` command creates the playlist automatically if Spotify does not already have one with the configured name.

That means the normal workflow for a brand-new client is:

1. create or choose a profile JSON
2. set the desired `playlist_name`
3. run `electro_analyzer.cli playlist`
4. if Spotify cannot find that playlist name in your account, the CLI creates it and fills it

Minimal example:

```bash
python3.11 -m electro_analyzer.cli playlist \
  --profile-config profiles/your_profile.json \
  --rotation-tracks 15 \
  --max-tracks 120 \
  --force
```

If you want to override the name at runtime:

```bash
python3.11 -m electro_analyzer.cli playlist \
  --profile-config profiles/your_profile.json \
  --playlist-name "New Client Playlist" \
  --rotation-tracks 15 \
  --max-tracks 120 \
  --force
```

Public/private visibility:

```bash
python3.11 -m electro_analyzer.cli playlist \
  --profile-config profiles/your_profile.json \
  --playlist-name "New Client Playlist" \
  --private \
  --rotation-tracks 15 \
  --max-tracks 120 \
  --force
```

Recommended first run for a new client:

```bash
python3.11 -m electro_analyzer.cli playlist \
  --profile-config profiles/your_profile.json \
  --playlist-name "New Client Playlist" \
  --rotation-tracks 15 \
  --max-tracks 120 \
  --dry-run
```

Then, if the preview looks right, rerun without `--dry-run`.

Notes:

- the playlist is created in the Spotify account used during OAuth login
- creation is name-based, so be deliberate with `playlist_name`
- if a playlist with that exact name already exists, the CLI refreshes it instead of creating a second one

## 7. Resolve Track IDs Before a Refresh

Use this when:

- the playlist is landing too short on hours
- many profile entries only contain text queries
- you changed a profile and want stable IDs plus `duration_ms`

Command:

```bash
python3.11 scripts/resolve_track_ids.py profiles/duques.json \
  --client-id "$SPOTIFY_CLIENT_ID" \
  --client-secret "$SPOTIFY_CLIENT_SECRET" \
  --redirect-uri "$SPOTIFY_REDIRECT_URI"
```

What it does:

- searches Spotify for each `query`
- stores `id`
- stores `duration_ms` when available
- pauses between batches to respect rate limits

After it completes, rerun the playlist refresh.

## 9. Redistribute Existing Spotify Tracks

This is only for tracks that already exist on Spotify and have `spotify:track:...` URIs.

Prepare a text file with one URI per line:

```text
spotify:track:...
spotify:track:...
spotify:track:...
```

Then interleave them every 10 tracks:

```bash
python3.11 -m scripts.redistribute_tracks \
  spotify:playlist:3s3Xy455ODEMaEPFcoENhW \
  new_tracks.txt \
  --interval 10
```

Notes:

- this rewrites the playlist order
- this does not work for local-only collaborator MP3/WAV files
- local files must be distributed to Spotify first before they can be inserted into a Spotify playlist

## 10. Promo Workflow

Promo audio is not part of Spotify playlists.

There are two separate promo workflows in this repo:

1. Web page playback with a scheduled promo clip
2. Offline insertion of a promo clip into a long audio file

Key files:

- `embed_player.html`
- `promo.txt`
- `promo_voice.mp3`
- `promo_clip.mp3`

Insert a short promo into a long MP3 every 20 minutes:

```bash
.venv/bin/python -m scripts.insert_promos DuquesBarbershop-April.mp3 promo.mp3 --interval-minutes 20
```

Important:

- this is for local audio files, not Spotify playlists
- rotating a Spotify playlist does not change promo playback assets

## 11. Troubleshooting

### CLI asks for `Client id:`

The Spotify env vars are missing in the current shell.

Fix:

```bash
export SPOTIFY_CLIENT_ID="..."
export SPOTIFY_CLIENT_SECRET="..."
export SPOTIFY_REDIRECT_URI="http://localhost:8080/callback"
```

### Refresh says success but Spotify looks unchanged

Check:

- you are looking at the same playlist ID that the CLI printed
- Spotify app/web player has refreshed
- the first ten tracks can still overlap with previous runs if the daypart block is similar

Use:

```bash
python3.11 -m scripts.list_playlist_tracks spotify:playlist:3s3Xy455ODEMaEPFcoENhW > playlist_dump.txt
```

### Playlist is too short in hours

Resolve track IDs first, then rerun refresh:

```bash
python3.11 scripts/resolve_track_ids.py profiles/duques.json \
  --client-id "$SPOTIFY_CLIENT_ID" \
  --client-secret "$SPOTIFY_CLIENT_SECRET" \
  --redirect-uri "$SPOTIFY_REDIRECT_URI"
```

### Search/rate-limit issues

If `resolve_track_ids.py` pauses repeatedly, let it finish. It batches requests intentionally to avoid Spotify rate limits.

### Promo insertion sounds wrong

Use the current `scripts.insert_promos` wrapper only. It normalizes chunk export so the promo clip does not slow down during long-file insertion.

## 12. Safe Operator Sequence

For a normal Duques refresh:

1. Activate the project env.
2. Export Spotify credentials.
3. Optionally run a dry run.
4. If durations are stale or missing, run `resolve_track_ids.py`.
5. Run the live `electro_analyzer.cli playlist` refresh.
6. If needed, dump playlist contents with `list_playlist_tracks.py`.
7. Leave promo files alone unless you are explicitly changing the promo workflow.
